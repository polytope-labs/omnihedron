## Docker image

Omnihedron is published to Docker Hub as `polytopelabs/omnihedron`.

```bash
docker pull polytopelabs/omnihedron:latest
```

Tags follow semver (`v0.1.0`, `v0.2.0`, etc.) plus SHA-based tags for each release.

## Health check

The image ships a built-in `HEALTHCHECK` running `omnihedron healthcheck`, which GETs
`/health` and exits `0` on a 2xx response, `1` otherwise. The image has no `curl` or
`wget`; do not use `curl`-based health checks.

```yaml
healthcheck:
  test: ["CMD", "omnihedron", "healthcheck"]
  interval: 10s
  timeout: 5s
  retries: 3
  start_period: 30s
```

An explicit compose `healthcheck` overrides the image's.

| Flag | Env var | Default | Description |
|---|---|---|---|
| `--url` | `OMNIHEDRON_HEALTHCHECK_URL` | `http://127.0.0.1:<port>/health` | Full URL to probe (overrides `--port`) |
| `--port` / `-p` | `OMNIHEDRON_PORT` | `3000` | Port the local server listens on |
| `--timeout` | `OMNIHEDRON_HEALTHCHECK_TIMEOUT` | `3` | Request timeout in seconds |

The check inherits the container's environment but not its `command:` arguments. If the
port is set only via `command: ["--port", "4000"]`, set `OMNIHEDRON_PORT=4000` instead (or
pass `--port 4000` in the healthcheck test).

Exit codes: `0` when `/health` returns 2xx; `1` when the probe fails (non-2xx, including
`503` when the database is down or the server is shutting down, timeout, connection error);
`2` on invalid arguments. Docker treats any non-zero exit as unhealthy.

## Docker Compose (development)

The repository includes a development compose file at `docker/docker-compose.yml`:

```bash
cd docker
docker compose up -d
```

This starts:

| Service | Description | Port |
|---|---|---|
| `postgres` | PostgreSQL 17 with fixture data | `5433` |
| `db-init` | One-shot fixture loader (skips if DB already populated) | — |
| `subql-query-ts` | TypeScript `@subql/query` for comparison | `3001` |
| `omnihedron` | Rust service (built from local Dockerfile) | `3000` |

The development compose file is **idempotent** — it checks whether the database already has data before loading fixtures, so it's safe to restart without duplicating data. It also uses a named volume (`subql_postgres_data`) so your data survives restarts.

You can set the schema name via environment variable:

```bash
SCHEMA_NAME=my_schema docker compose up -d
```

## Docker Compose (CI)

The CI compose file at `docker/docker-compose.ci.yml` is stripped down:

- **No persistence** — no named volumes, data is ephemeral
- **No idempotency check** — always loads fixtures fresh
- **No omnihedron container** — CI builds and runs the binary on the host

The CI workflow uses this to spin up PostgreSQL + TypeScript for integration testing.

## Building the image locally

The Dockerfile expects a pre-built binary:

```bash
# Build the binary first
cargo build --release

# Then build the Docker image
docker build -t omnihedron:latest -f docker/Dockerfile .
```
